# Полноценный чат с 1С:Напарником через EDT-MCP

Дата исследования: **8 октября 2026 года**. Материалы подготовлены для обращения к разработчикам и возможной самостоятельной доработки.

**Главный результат:** через MCP удалось вести последовательную беседу с сохранением контекста, читать конфигурацию, использовать серверные инструменты ИТС и подзадач, а также объявить и исполнить свой локальный инструмент. Это эксперимент на внутреннем Java API установленного Напарника, а не готовый стабильный публичный интерфейс полного чата.

## Важное различие репозиториев

Материалы перенесены в отдельный checkout **EDT-MCP**, созданный из форка **https://github.com/Nicodimych/EDT-MCP**. Его upstream — **https://github.com/DitriXNew/EDT-MCP**. Каталог `feenlace/mcp-1c` содержит другой Go-сервер и расширение 1С; он сохранён в архиве и больше не является рабочим проектом этого исследования.

В текущем форке добавлена только документация, доказательства и безопасные диагностические примеры. Реализация stateful-чата ещё не внесена. Установка плагина в EDT не выполнялась.

## Уровни доказательств

| Метка | Значение |
|---|---|
| `LIVE-MCP` | Наблюдались запрос, исполнение и результат через MCP/внутренний Java API |
| `LIVE-LOCAL` | Проверен локальный исполнитель или каталог внутри EDT без полного хода модели |
| `USER-UI` | Пользователь сообщил результат продолжения беседы в штатной панели |
| `STATIC` | Вывод из исходников EDT-MCP или разбора классов установленного Напарника |
| `PROPOSAL` | Предлагаемая реализация, которой ещё нет |
| `UNVERIFIED` | Нужна отдельная проверка |

## Состояние возможностей

| Возможность | Результат |
|---|---|
| Текстовый вопрос → ответ → уточнение в той же беседе | `LIVE-MCP`, успешно |
| Напарник сам читает свойства конфигурации через JShell и EDT-MCP bridge | `LIVE-MCP`, успешно |
| Родные инструменты Напарника | Каталог из 26; родной GetProjects отдельно исполнен, `LIVE-LOCAL` |
| Серверные TodoWrite, Task, TaskResult | `LIVE-MCP`, получены результаты |
| Search_ITS и Fetch_ITS | `LIVE-MCP`, получены документы, включая чтение конкретной ссылки |
| Свой IMcpTool с отдельным локальным обработчиком | `LIVE-MCP`, успешно, один вызов с уникальной меткой |
| Чтение обычной web-страницы через mcp__web__fetch | `USER-UI`, успешно; полный внешний цикл с точным именем ещё не повторён |
| Отдельный общий поиск WebSearch / mcp__web__search | Не подтверждён; в панели сообщалось об отсутствии |
| Структурированная карточка вопроса/выбора и ответ на неё через native API | `UNVERIFIED` |
| Подтверждение изменения через native API | `UNVERIFIED` |
| Восстановление ConversationSession после перезапуска EDT | `UNVERIFIED`; восстановление MCP transport отдельно проверено |
| Полное совпадение поведения API и панели | Не доказано |

## Обстановка испытаний

- Windows, EDT `2026.2.1.3`, Напарник `1.0.8.v202609241142`.
- EDT-MCP `2.20.1`, протокол `2025-11-25`, локальный endpoint `http://127.0.0.1:8765/mcp`, 99 инструментов.
- Xelgo EDT Extension Tweaks `1.1.22.v202608042058`.
- Успешная комбинация native запроса: `skillName="custom"`, `chat=true`, сохранение возвращённой `ConversationSession`.
- `chat=true` внутри SendUserMessageRequest **не равен** `mode="chat"` инструмента ask_workmate.

После экспериментов пользователь сообщил о необходимости перезапуска EDT. Причина необходимости перезапуска не установлена. MCP после перезапуска пользователь запустил вручную. Свежий снимок соединения сохранён в [evidence](evidence/). Это не доказывает повторную проверку всех функций на новом процессе EDT.
