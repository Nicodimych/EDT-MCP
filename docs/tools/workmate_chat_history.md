# workmate_chat_history

Read the journal of a stateful 1C:Workmate conversation created with workmate_chat_create: the messages sent, Workmate's finished answers and the errors, oldest first. The journal is written when a send COMPLETES, so poll the send's jobId with get_job_status before reading the newest exchange. Read-only.

## Parameters
| Parameter | Required | Type | Description |
| --- | --- | --- | --- |
| chatId | yes | string | Chat id returned by workmate_chat_create. |
| limit | — | integer | Optional maximum number of journal entries to return, counting from the NEWEST; omit to return the whole journal (capped at 200 entries per chat). |

## Guide
Reads the journal of a stateful 1C:Workmate conversation created with
`workmate_chat_create`: messages sent, Workmate's finished answers and errors, oldest first.

The journal is written when a send COMPLETES, not when it starts. Poll the send's jobId with
`get_job_status` before expecting the newest exchange to appear here.

## Example

```json
{"chatId": "2d3f...", "limit": 2}
```

Result:

```json
{
  "success": true,
  "chatId": "2d3f...",
  "turns": [
    {"seq": 3, "role": "user", "text": "Now detail the largest one", ...},
    {"seq": 4, "role": "assistant", "text": "...", "declaredFinal": true, ...}
  ],
  "hasSessionCursor": true,
  "sendInFlight": false
}
```

`turns` are ordered chronologically (oldest first, newest last), and `seq` is 1-based ascending (`1..N`) across the chat's journal (when `limit` is used, `seq` reflects the entry's position in the full journal, e.g. `3, 4` of 4). Reading `workmate_chat_history` also clears the chat's `hasUnread` flag in `workmate_chat_list`.

`role` is `user`, `assistant` or `error`. An `error` turn means the send failed; the
conversation cursor was NOT advanced by that attempt, so the chat can be continued from the
last confirmed point.
