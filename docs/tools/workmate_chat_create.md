# workmate_chat_create

Create a local handle (chatId) for a STATEFUL conversation with 1C:Workmate: every workmate_chat_send with this chatId lands in the SAME cloud conversation, so Workmate keeps the context of everything said before. Creating the chat starts no cloud conversation and sends nothing - the first send does. The record lives in EDT's memory and is lost when EDT restarts. Parameters and examples: get_tool_guide('workmate_chat_create').

## Parameters
| Parameter | Required | Type | Description |
| --- | --- | --- | --- |
| projectName | — | string | Optional open EDT project name used as Workmate's context for every send of this chat. Omit only on Workmate builds with a default project context; newer builds require it for conversations. Use list_projects to discover valid names. |
| skillName | — | string | Optional Workmate skill name applied to every send. Omit to use 'custom', the skill under which Workmate runs its own tool loop; 'raw' answers from the model alone and inspects nothing. |
| maxToolRounds | — | integer | Optional positive limit for Workmate's internal tool-call rounds, applied to every send of this chat unless overridden in workmate_chat_send; defaults to 80. |
| title | — | string | Optional human-readable label for this chat, returned by workmate_chat_list. |

## Guide
Creates a local handle (chatId) for a STATEFUL conversation with 1C:Workmate. Every
`workmate_chat_send` with this chatId lands in the SAME cloud conversation, so Workmate keeps
the context of everything said before — unlike `ask_workmate`, where every call starts a new
conversation.

Creating the chat starts NO cloud conversation and sends nothing. The record lives in EDT's
memory and is lost when EDT restarts.

## Examples

Create a chat over an open project:

```json
{
  "projectName": "MyConfiguration",
  "title": "Refactoring research"
}
```

Result: `{"success": true, "chatId": "...", ...}`. Pass that `chatId` to
`workmate_chat_send`.

## Typical flow

1. `workmate_chat_create` → chatId.
2. `workmate_chat_send` (chatId, message) → jobId; poll with `get_job_status`.
3. `workmate_chat_history` (chatId) → the finished exchange.
4. Repeat 2–3: every send continues the same cloud conversation.

See `workmate_chat_send` for the full loop.
